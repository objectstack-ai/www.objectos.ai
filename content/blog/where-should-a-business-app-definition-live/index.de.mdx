Wenn AI-Agents Ihre Unternehmenssoftware ändern, halten Sie die Masterkopie ihrer Regeln als Dateien in einem Repository, das Ihr Unternehmen kontrolliert, und bauen Sie das laufende System aus diesen Dateien. Jede Änderung kommt dann als datierter, unterschriebener Vorher-Nachher-Vergleich mit schriftlicher Begründung, sodass sich „Wer hat dem Vertrieb das erlaubt, und warum?" aus den Aufzeichnungen beantworten lässt, nicht aus dem Gedächtnis. Der Preis ist ein doppelter. Die etablierten Plattformen (Salesforce, Odoo und ihre Verwandten) bringen Jahre an Produktionseinsatz, fertige App-Pakete und Partner mit; eine Repository-first-Plattform heißt, mehr selbst zu bauen. Und jede Änderung muss im Repository vorgeschlagen und angenommen werden, ein Schritt, den eine Admin-Oberfläche nicht verlangt.

*Gemessen auf ObjectStack 18.6.0, der Version, die eine Neuinstallation heute bekommt: die Git-Historie des Open-Source-CRM-Beispiels am Release-Tag und das veröffentlichte Kommandozeilenwerkzeug 18.6.0, ausgeführt gegen dieses Beispiel. Alle Befehle stehen in [Der Beweis](#der-beweis).*

## Konfiguration oder Definition: Welche Kopie gewinnt?

Beide Arten von Plattform erledigen dieselbe sichtbare Aufgabe. Sie beschreiben Ihr Geschäft (Kunden, Verkaufschancen, wer was bearbeiten darf), und die Plattform macht aus dieser Beschreibung Datenbanktabellen, Bildschirme und eine Programmierschnittstelle (eine API). Eine Plattform, die so arbeitet, heißt Metadaten-Plattform: Die Beschreibung, nach der sie läuft, sind Metadaten, also Daten über Ihre Daten. ObjectStacks eigene [Vergleichsseite](/en/compare/) nennt diese Plattformen [„die nächsten Verwandten"](https://github.com/objectstack-ai/objectstack/blob/958ee03594968c651db1bc40ecb05bfe72f94b2d/content/docs/concepts/compare.mdx#L58-L73): „Die Metadaten von Salesforce sind der Vorfahr; zu den Open-Source-Cousins gehören Frappe Framework mit ERPNext, Odoo, NocoBase, Payload und Twenty." Den Unterschied benennt sie in einem Satz:

> Wo die Definition liegt und für wen sie geschrieben ist. In den meisten dieser Plattformen sind Metadaten Konfiguration, die in der Datenbank der Plattform gespeichert und über ihre Oberfläche bearbeitet wird; wo es Code ist, wie bei der Payload Config oder den Modulen von Odoo, ist es Framework-Code.

Framework-Code heißt hier: Code, der für genau diese eine Plattform geschrieben ist. Die nützliche Frage für einen Käufer ist enger als „Metadaten oder Code". Sie lautet: **Welche Kopie ist maßgeblich?** Die maßgebliche Kopie ist diejenige, die gewinnt, wenn das laufende System und irgendeine andere Kopie voneinander abweichen.

- **Konfiguration.** Die Datenbank des laufenden Systems hält die maßgebliche Kopie. Sie ändern das System, indem Sie sie ändern, meist über eine Admin-Oberfläche, und eine Datei, falls Sie eine führen, beschreibt, was läuft.
- **Definition.** Eine Reihe von Dateien in Ihrem Repository hält die maßgebliche Kopie, und das laufende System wird aus ihnen gebaut. Sie ändern das System, indem Sie eine Datei ändern, und die Änderung wird nach dem Build wirksam, dem Schritt, der die Dateien in das laufende System verwandelt.

Das sind zwei Arbeitsweisen, keine zwei Herstellerlisten. Mehrere der oben genannten Plattformen lassen sich auch aus Dateien betreiben; fragen Sie jeden Hersteller, wie seine Kunden tatsächlich arbeiten. ObjectStack, das diesen Beitrag veröffentlicht, gehört zur Repository-first-Sorte.

![Zwei Arten, die Regeln einer Business-App zu halten. Links eine Definition: Die Dateien in Ihrem Repository sind die maßgebliche Kopie, und jede Änderung daran ist ein Diff mit Namen und schriftlicher Begründung; der Build prüft die Dateien und macht daraus das laufende System, das bei jedem Deployment aus ihnen neu gebaut wird. Rechts Konfiguration: Ein Administrator ändert Einstellungen in einer Admin-Oberfläche, das laufende System und seine Datenbank sind die maßgebliche Kopie, und eine Datei, falls man eine führt, beschreibt, was läuft](./two-copies-en.svg)

Ein Repository ist ein versionierter Ordner, meist auf GitHub oder GitLab gehostet, der jede Änderung als Vorher-Nachher mit Autor, Datum und Nachricht aufbewahrt. Dieses Vorher-Nachher heißt Diff. Ein Pull Request ist eine vorgeschlagene Änderung in dieser Form, die jemand in die Hauptkopie übernimmt. Beide Arten von Plattform können Historie führen; dieser Beitrag behauptet nichts über die eigene Änderungsverfolgung irgendeines Herstellers, prüfen Sie sie also für die Plattform, die Sie abwägen. Die Wahl entscheidet, wo „Was gilt gerade, und seit wann?" beantwortet wird und wo eine Änderung gelesen wird, bevor sie wirkt: in der Historie einer Datei oder in den eigenen Aufzeichnungen und Werkzeugen der Plattform.

Das wiegt schwerer, seit ein AI-Agent viele der Änderungen schreibt. Im Beispiel unten ist bei jeder der sieben Änderungen an der Rechtedatei der Vertriebsrollen ein AI-Coding-Agent als Mitautor eingetragen.

## Eine Rechteänderung, nachverfolgt

Das Repository von ObjectStack liefert ein Open-Source-CRM-Beispiel mit, eine Demo-App und kein Kundensystem. Im August 2026 konnte seine Vertriebsrolle Verkaufschancen öffnen, ihnen aber keine Produktpositionen hinzufügen: Die Plattform wies jeden Benutzer ab, der kein Administrator war. Die Korrektur fügte eine Rechtezeile hinzu und eine Zeile in der Zugriffstabelle der App: einer im Repository gespeicherten Liste dessen, was jede Rolle anlegen, lesen, bearbeiten und löschen darf. Wir haben der Historie der Rechtedatei die Fragen gestellt, die eine Prüferin oder ein Finanzverantwortlicher stellen würde, und die Korrektur dann auf dem heutigen Release rückgängig gemacht, um zu sehen, was sie aufhält.

Die Ablehnung des Builds lautet so:

```text
✗ Access matrix drift (1 change) — capability changes must be reviewed
• 'crm_sales_user' loses ALL access to 'crm_opportunity_line_item' (entry removed)
If intended, re-run with --update-access-matrix and commit the snapshot — its diff IS the review artifact.
```

Im Klartext: Die Vertriebsrolle würde jeden Zugriff auf Produktpositionen von Verkaufschancen verlieren, und der Build wird nicht fertig, bis eine Person das bewusst akzeptiert. Die „Access Matrix" ist die im Repository gespeicherte Zugriffstabelle, eine Zeile je Rolle und Datensatztyp. Der Mechanismus, Zeile für Zeile, steht in [Wie fängt man eine stille Rechteänderung einer AI ab, bevor sie ausgeliefert wird?](/de/blog/catch-ai-silent-permission-change-access-matrix-gate/)

## Was die Metadaten-Plattformen besser machen

Die Argumente für die etablierten Plattformen sind stark, und die Dokumentation von ObjectStack führt sie mit eigenen Worten an. Ihre Stärke: [„Business-Anwendungen schnell auf einer bewährten Laufzeit bauen, mit App-Paketen, Modulen und Integrationen als Ausgangspunkt."](https://github.com/objectstack-ai/objectstack/blob/958ee03594968c651db1bc40ecb05bfe72f94b2d/content/docs/concepts/compare.mdx#L65-L66) Wo sie vorne liegen:

> Salesforce, Odoo und ERPNext bringen Jahre an Produktionseinsatz, fertige Anwendungen, App-Marktplätze und Implementierungspartner mit. ObjectStack ist jünger; rechnen Sie damit, mehr selbst zu bauen.
> — [ObjectStack-Dokumentation, „Wo die anderen stärker sind"](https://github.com/objectstack-ai/objectstack/blob/958ee03594968c651db1bc40ecb05bfe72f94b2d/content/docs/concepts/compare.mdx#L115-L117)

Drei weitere Punkte sprechen für sie:

- **Auch Agents erreichen sie.** Dieselbe Seite sagt: [„Mehrere von ihnen bieten inzwischen MCP-Server an, sodass auch Agents sie erreichen."](https://github.com/objectstack-ai/objectstack/blob/958ee03594968c651db1bc40ecb05bfe72f94b2d/content/docs/concepts/compare.mdx#L62-L63) MCP ist der offene Standard, über den AI-Agents die Werkzeuge eines Systems aufrufen.
- **Logik als Daten zu speichern ist die normale Form, kein Mangel.** [„Das ist derselbe Kompromiss, den ServiceNow (Business Rules), Salesforce (als Metadaten gespeicherte Formulas und Apex Triggers), Retool (Transformer-JS-Strings) und Airtable (Scripting Blocks) eingegangen sind. Es ist die übliche Low-Code-Form."](https://github.com/objectstack-ai/objectstack/blob/958ee03594968c651db1bc40ecb05bfe72f94b2d/content/docs/automation/hook-bodies.mdx#L61) Das ist ObjectStacks eigene Dokumentation, über die Entscheidung, kleine Stücke Geschäftslogik als Daten zu halten. Der Unterschied liegt also nicht darin, ob eine Plattform Metadaten nutzt. ObjectStack ist eine Metadaten-Plattform. Der Unterschied liegt darin, wo die maßgebliche Kopie versioniert wird.
- **Eine Admin-Oberfläche braucht kein Repository.** Auf einer Konfigurationsplattform kann eine Fachadministratorin in wenigen Minuten ein Feld hinzufügen, ohne Pull Request, Build oder Deployment. Für viele Teams ist genau das der Punkt.

Wenn Sie bereits auf einer dieser Plattformen arbeiten, ist das, was Sie dort schon gebaut haben, ein echter Grund zu bleiben, und unsere Beiträge zu [Power Platform und Dataverse](/de/blog/power-platform-lock-in-dataverse-self-host/) und zu [Retool](/de/blog/retool-vs-ai-native-app-platform/) wägen konkrete Produkte ab.

## Wie man wählt

**Beginnen Sie mit einer Konfigurationsplattform**, wenn Sie App-Pakete, einen Marktplatz und Implementierungspartner noch in diesem Quartal brauchen; wenn die Menschen, die das System ändern, Administratoren sind, die in seinen Oberflächen arbeiten; und wenn Ihre Prüfer die eigenen Änderungsaufzeichnungen der Plattform akzeptieren.

**Halten Sie die Definition in einem Repository**, wenn AI-Agents die meisten Änderungen schreiben und ein Mensch für jede einzelne geradestehen muss; wenn eine Rechteänderung mit Begründung und lesbarem Vorher-Nachher kommen muss; und wenn die Definition Ihres Geschäfts aus Dateien bestehen soll, die Ihr Unternehmen hält, nicht aus Zeilen in der Datenbank eines laufenden Systems. Das README von ObjectStack sagt den letzten Punkt so: [„Die Definition liegt als gewöhnliches TypeScript in Ihrem Repository, versioniert in Ihrem VCS und als Diff reviewbar – kein Graph, der im System eines Herstellers gehalten wird."](https://github.com/objectstack-ai/objectstack/blob/958ee03594968c651db1bc40ecb05bfe72f94b2d/README.md#L197-L199) VCS ist Versionskontrolle; TypeScript ist die Sprache, in der die Dateien geschrieben sind.

Welche Sie auch wählen, stellen Sie dem Hersteller drei Fragen:

1. Welche Kopie ist maßgeblich: das laufende System oder eine Datei?
2. Bekomme ich jede Rechteänderung als lesbares Vorher-Nachher, mit Autor und Begründung, bevor sie wirkt?
3. Wenn laufendes System und Datei voneinander abweichen, welche gewinnt, und wer bemerkt es?

## Was ein Repository nicht löst

- **Es entscheidet nicht, ob eine Änderung richtig ist.** Als wir die August-Korrektur entfernten, bestand die erste Prüfung der Plattform mit einer Warnung. Nur die Zugriffstabelle stoppte den Build, und nur, weil diese App eine hat: Jede App muss die Tabelle selbst einschalten, und eine App ohne sie wäre gebaut worden. Ob der Vertrieb Produktpositionen anfassen darf, muss weiterhin ein Mensch entscheiden.
- **Es erzeugt kein Review.** Sechs der sieben Pull Requests oben haben auf GitHub keine Review-Aufzeichnung, unsere eigenen mitgezählt: Das ist das eigene Repository von ObjectStack. Keine Aufzeichnung beweist nicht, dass niemand die Änderung gelesen hat; es heißt, dass niemand zeigen kann, dass es jemand getan hat. Das Repository macht diese Lücke zählbar. Sie zu schließen, verlangt eine Einstellung, die vor dem Mergen eine Freigabe erzwingt.
- **Auch ObjectStack hält etwas Konfiguration.** Ansichten, Dashboards, Berichte, Übersetzungen und E-Mail-Vorlagen lassen sich in der Admin-Oberfläche einer laufenden Umgebung bearbeiten. Diese Änderungen liegen in der Datenbank dieser Umgebung und [haben Vorrang vor der Version im Repository](https://github.com/objectstack-ai/objectstack/blob/958ee03594968c651db1bc40ecb05bfe72f94b2d/content/docs/concepts/metadata-lifecycle.mdx#L43), mit einem eigenen Änderungsprotokoll. Die meisten Arten von Definition, Rechtebündel eingeschlossen, lassen sich außerdem [zur Laufzeit über die Programmierschnittstelle anlegen](https://github.com/objectstack-ai/objectstack/blob/958ee03594968c651db1bc40ecb05bfe72f94b2d/packages/spec/src/kernel/metadata-plugin.zod.ts#L348). Das ist Konfiguration im Sinne dieses Beitrags, und welche Änderungen durch das Repository müssen, ist eine Regel, die Sie festlegen.
