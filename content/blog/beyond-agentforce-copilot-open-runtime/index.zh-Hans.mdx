一家公司做 AI agent 选型，入围名单很自然：Agentforce、Copilot Studio、ServiceNow AI Agents。三家都强，都有人推荐。

评估到一半，团队发现一件尴尬的事：**没有一家合适，而且原因都一样。**

Agentforce 在 CRM 里最强——可这家公司的客户数据只有一部分在 Salesforce，另一部分在自建系统里。Copilot Studio 在 Teams、365 里最顺——可它的核心业务流程不在 Office 里。ServiceNow 在 ITSM 里是王者——可它要管的远不止工单。每一家单独看都很能打，放到这家公司真实的、横跨多个系统的处境里，又都差了一口气。

问题不在这三家不够好。问题在它们共享的一个前提——而这个前提，对这家公司不成立。

## 那个没说出口的前提：你的世界都在一家墙里

这些套件的强，本质是"**生态内最优**"。Agentforce 假设你的客户、流程、对象都已经在 Salesforce 里；Copilot Studio 假设你的协作、文档、身份都在 365 里；ServiceNow 假设你的流程都在它上面。前提成立时，它们确实省心——数据现成、权限现成、集成现成，agent 几乎顺手就接上。

可这个前提，对大多数企业并不成立。真实的企业长这样：CRM 一家、ERP 另一家、工单第三家，外加一堆自建系统和电子表格；它们想保留模型选择权，因为模型一年一个样；它们受监管约束，数据不能随便出域。对这样的企业，"生态内最优"反而成了约束——因为你的世界根本不在任何一家的墙里。

## 摊开比：不是谁更好，是各自适合谁

| 维度 | 封闭套件（Agentforce / Copilot / ServiceNow） | 开放自托管运行时（ObjectStack / ObjectOS） |
| --- | --- | --- |
| 最适合 | 业务已重度集中在该生态内 | 数据散在多系统、跨栈、要自持 |
| 数据位置 | 厂商云 | 你自己的基础设施 |
| 模型选择 | 偏向自家或绑定模型 | 自由换，模型在外、运行时在内 |
| 业务定义归属 | 长在平台里 | 你仓库里的开放协议元数据（Apache 2.0） |
| 计费 | 按动作 / 按席位 | 按运行时与基础设施，与用量解耦 |
| 起步姿态 | 先把业务搬进生态 | 扩展存量系统，不要求先迁移 |

这张表没有"全对"的一列。

## 先泼一盆冷水：别为了开放而选开放

把话说到前头，免得这篇变成单方面的安利。

**开放、自托管，是有代价的——你得自己运营它。** 打补丁、保证可用性、管好密钥和升级，这些活以前是厂商替你担的，自托管之后落到你头上。如果你没有平台团队，套件那种"开箱即用、出事有人接电话"的托管体验，很可能比一套你得自己照看的运行时更划算、更省心。

而且，如果你 90% 的业务确实就在 Salesforce 里、也不在意数据出域、不打算换模型——那 Agentforce 多半就是最优解，没必要为了"不被锁定"这个尚未发生的风险，去承担眼前实实在在的运营负担。**开放自托管不是更高尚的选择，它是为特定处境准备的选择。** 选错了处境，它就是负担。

那它对的处境，是右列那些约束**同时**出现的时候——这恰恰是越来越多中大型、受监管、多系统企业的真实样子，也是开头那家公司的样子。

## 开放自托管，到底换来什么

如果你属于右列，那"开放 + 自托管"换来的不是情怀，是具体的能力。最能说明问题的，是它对待存量系统的姿态。

套件希望你的世界搬进它的墙；开放运行时假设你的世界本来就是散的，它的活是让既有系统原生支持 AI，而不是先迁移。回到开头那家公司——它的客户数据一半在 Salesforce、一半在自建系统。在 ObjectOS 上，它可以用一份定义，把两边收成同一个"客户"：

```ts
export const Customer = ObjectSchema.create({
  name: 'crm_customer',
  label: '客户',
  sources: [
    Source.salesforce('Account'),        // 一半在这
    Source.database('legacy.customers'),  // 另一半在这
  ],
});
```

agent 面对的是这**一个**统一的、带权限和审计的"客户"，而不是两个互不相认的系统。业务定义是你仓库里可 diff、可迁移的元数据；运行时跑在你自己的基础设施上，强制权限、记录审计；模型可以来自外部任何一家，但承载对象、权限、动作和证据的运行时是你的。你没有把"自己业务的定义"交给任何一家保管。

## 一个诚实的选择题

所以这不是"谁该被淘汰"，是"你站在哪一边"。问自己三个问题：

1. 我的业务，是基本都在某一家生态里，还是散在多个系统中？
2. 我能不能接受数据持续流向厂商云？合规上签得了字吗？
3. 我**有没有团队**去运营一套自托管的运行时？

前两个答案偏"散的、不能"，第三个偏"有"——那你要找的，本来就不是又一个更强的封闭套件，而是 Agentforce、Copilot Studio 之外的另一种东西。如果三个答案都偏向另一边，那就大方用套件，它们确实好用。诚实地对号入座，比追逐谁家功能更新重要得多。

## 结语

封闭套件赢的是"生态内最优"，这个优势在它的前提成立时非常真实，不该被否认。开放自托管运行时赢的是"前提不成立时仍然成立"——当你的世界是散的、数据要自持、模型要自由、定义要握在自己手里，并且你担得起自己运营它的那份责任。

知道自己站在哪一边，也知道为此要付什么代价——比任何一家的功能列表都重要。
