**결론부터 말하면:** AI 프로젝트 어시스턴트는 또 하나의 보드가 아니라, 프로젝트·작업·회의·리스크·변경·실행 계획을 메타데이터로 모델링하는 것이다. 그래서 AI가 진행 업데이트에 숨은 리스크를 드러내고, 그 대응은 여전히 구체적인 행동으로 이어진다.

많은 기업이 채팅 창으로 AI를 시작합니다. 하지만 실제 업무에는 그것만으로 부족합니다. 애플리케이션은 요청 뒤에 있는 객체, 규칙, 권한, 워크플로, 증거를 이해해야 합니다.

아래의 예시는 자연어 요구를 객체, 필드, 권한, 자동화, Agent 도구로 나누어 사람이 검토할 수 있는 메타데이터로 바꾸는 과정을 보여줍니다.

> 업무 사용자가 자연어로 요구사항을 설명할 수 있도록 이 애플리케이션을 만들어 주세요. 객체, 필드, 뷰, 규칙, 권한, 통제된 AI 액션을 생성해 주세요. 사용 단계에서도 자연어로 질문하고, 수정하고, 검토하고, 작업을 실행할 수 있어야 합니다.


## 이 애플리케이션이 AI-native인 이유

AI-native는 모델을 한 번 호출하는 것이 아닙니다. 자연어 입력, 비정형 정보, 업무 규칙, 운영 액션이 함께 작동하는 것입니다. AI는 맥락을 읽고 제안하지만, 실제 실행 가능 여부는 플랫폼이 판단합니다.

## 기반이 되는 메타데이터

Builder가 먼저 생성해야 하는 것은 실행 가능한 업무 모델입니다. 핵심 객체는 다음과 같습니다.

| Object | Role |
| --- | --- |
| `project` | UI, API, 워크플로, 권한, AI 도구에서 사용하는 통제된 업무 객체. |
| `milestone` | UI, API, 워크플로, 권한, AI 도구에서 사용하는 통제된 업무 객체. |
| `task` | UI, API, 워크플로, 권한, AI 도구에서 사용하는 통제된 업무 객체. |
| `meeting_note` | UI, API, 워크플로, 권한, AI 도구에서 사용하는 통제된 업무 객체. |
| `project_risk` | UI, API, 워크플로, 권한, AI 도구에서 사용하는 통제된 업무 객체. |
| `change_request` | UI, API, 워크플로, 권한, AI 도구에서 사용하는 통제된 업무 객체. |
| `action_plan` | UI, API, 워크플로, 권한, AI 도구에서 사용하는 통제된 업무 객체. |

이 객체들은 단순한 테이블이 아닙니다. AI가 읽을 수 있는 정보, 민감한 데이터, 확인이 필요한 액션, 감사에 남겨야 할 판단을 정의합니다.

## 자연어로 계속 발전시키기

첫 버전 이후에도 업무팀은 새 규칙을 자연어로 말할 수 있어야 합니다. 필수 필드, 리스크 조건, 승인 단계, 뷰 추가 같은 요청을 플랫폼은 프롬프트가 아니라 메타데이터 변경으로 바꿔야 합니다.

> 중요한 건을 자동으로 표시하고 관리자 뷰에 넣는 규칙을 추가해 주세요.

> AI가 제안을 만들 수는 있지만, 업무 변경을 저장하기 전에는 사람의 확인을 필수로 해 주세요.

## 앱 안에서 일하는 방식

> 오늘 가장 먼저 봐야 할 항목은 무엇이고, 이유는 무엇이며, 다음 액션은 무엇인가?

좋은 답변은 생성된 문장만이 아닙니다. 허용된 객체를 읽고, 이유를 설명하고, 부족한 정보를 보여주며, 실행 가능한 다음 액션을 제안합니다. 사용자는 필드를 찾기보다 업무 질문에서 시작할 수 있습니다.

## 경계가 있는 실행

요약, 분류, 내부 알림, 보고서 같은 낮은 위험 작업은 더 자동화할 수 있습니다. 작업 생성이나 상태 변경 같은 중간 위험 작업은 확인이 필요합니다. 고객 약속, 금전 이동, 계약, 권한, 데이터 내보내기, 감사 종료 같은 높은 위험 작업은 승인이 필요합니다.

## 실용적인 구현 순서

1. 핵심 객체와 관계를 모델링한다.
2. 기존 시스템, 문서, 채널을 연결한다.
3. 먼저 읽기 용도로 AI 요약, 분류, 분석을 활성화한다.
4. 쓰기 액션에 확인과 승인을 추가한다.
5. 반복적이고 위험이 낮은 액션부터 단계적으로 자동화한다.
