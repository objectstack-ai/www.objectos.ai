一个工程师，花了一个下午，把生产库包了一层 MCP server，让公司的 agent"连上了"。演示很顺，老板很满意。

第二天，销售随口问 agent："帮我把所有客户的合同金额导出成一张表。"

agent 很乐意地照做了——全公司的，一条不落。它没有恶意，它只是**很有帮助**。问题在于，那层下午赶出来的包装**没有身份的概念**：它不知道提问的是谁、那个人本来能看哪些数据。它对 agent 暴露的，是这个服务能碰的一切。

这不是一次黑客攻击，是一次"乐于助人"造成的泄露。而它之所以发生，恰恰是因为连接这件事，现在太容易了。

## 连接的仗，基本打完了——这正是风险所在

先承认这件大事：MCP 在一年内铺到了**上万台企业服务器、9700 万次 SDK 下载**，Anthropic、OpenAI、Google、微软、AWS 全站了进来；A2A 跨过 150 家组织、归了 Linux 基金会。agent"怎么连工具、怎么连别的 agent"，已经标准化了。

但成功本身制造了陷阱。连接这件事——大概占整个工程量的 80%——突然变得几小时就能搞定。于是真正难、也真正重要的那 20%（连上之后准不准做、做了记不记账），就特别容易被当成"以后再补"的事顺手略过。开头那个下午，就是这么来的。

这里值得借一个类比，但只借一次：MCP 像 TCP/IP，把"包怎么送到对面"标准化了。可没有人会把一个生产系统直接架在裸 TCP 上——它上面还得长出 TLS、长出身份、长出"谁能做什么、留什么证据"。agent 生态现在就停在"刚铺好 TCP/IP"的时刻，热闹是真的，但上面那层还没长出来。

## 把裸接口包成工具，等于发了张超级用户通行证

为什么"包一层就连上"这么危险？因为被包的那些接口，**当初是为可信的后端服务设计的，不是为一个会自己决策的 agent 设计的**。它们默认调用方已经鉴过权，所以自己不怎么校验身份。于是直接暴露成 MCP 工具时：

- agent 拿到的是一个**没有身份**的接口——它不是"以张三的身份查"，而是以服务的权限查所有；
- 它的写操作按**服务的权限**算，不是发起人的，出错无从归责；
- 这些调用**不进任何业务审计账**，事后查无可查。

一句话：把裸接口包成 MCP 工具，等于给 agent 发了一张超级用户通行证。协议越普及、连接越省事，这张通行证就发得越随手。

## 缺的那一层：每次调用都带身份、权限和留痕

协议之上真正该补的，是一个受治理的工具层——agent 调的不是裸接口，而是一组每次调用都走完和人一模一样关卡的受控动作：

![一次受治理的工具调用的生命周期：以用户身份发起、运行时核验权限、受控执行、写入审计](./tool-call-lifecycle.svg)

裸接口的做法是把中间三步全省掉，而省掉的恰好是"准不准做"和"记不记账"。关键是这三步**不能靠提示词**——"请只查有权限的数据"是建议不是关卡，一次越狱就绕过。权限核验必须在执行引擎里发生，人和 agent 走同一套。

## 先泼一盆冷水：它管的是"能不能"，不是"该不该"

这里要划清一条边界，否则容易神化它。

受治理的工具层，约束的是**爆炸半径**，不是**判断力**。它能保证 agent 做不了它无权做的事——这很重要，开头那次泄露就被它当场拦下。但它**拦不住一个"权限之内、却很蠢"的动作**：如果张三本来就有权给某客户打折，agent 以他的身份打了一个不该打的折，工具层会照常放行，因为这在权限之内。

换句话说，它解决的是"越权"和"无痕"，不解决"决策对不对"。后者还得靠评测、靠把高风险动作留给人审批、靠流程设计。谁要是告诉你"接上受治理工具层，agent 就绝对安全了"，那是夸大。它是必要的地基，不是全部的楼。

## 工具不该一个个手写，而该从定义里长出来

还有个很现实的反驳：那不就是要给每个接口手写一层权限和审计包装吗？几十上百个工具，写到何时？而且这堆胶水代码本身又成了没人读的技术债。

对。所以正确做法不是**手写**这层，而是让它从业务定义里**自动长出来**。你声明对象和权限——比如一个客服退款场景：

```ts
export const Refund = ObjectSchema.create({
  name: 'support_refund',
  fields: { amount: Field.currency({ label: '退款金额', min: 0 }) },
});

export const AgentRole: Security.PermissionSet = {
  name: 'support_agent',
  objects: {
    support_refund: { allowRead: true, allowCreate: true, allowEdit: false, allowDelete: false },
  },
};
```

运行时（ObjectOS）就**自动**把它投影成一组 agent 可调用的受治理工具：查询、创建退款，每个都内置上面那条权限的核验、以登录用户身份执行、落进统一审计账；"退款超额走审批"是挂在对象上的流程，工具命中时自动暂停等签字——这些都不用在工具代码里手写。

对照一下危险的版本，差别就清楚了：

```json
// 裸工具：把风险直接交给模型的"自觉"
{ "name": "run_sql", "description": "执行任意 SQL 查询", "params": { "sql": "string" } }
```

你不为每个工具写权限代码，你只声明权限；工具是定义的投影。MCP 负责"怎么连"，这层负责"连上之后准不准做、记不记账"——而且不用你手写。

## 结语

把 MCP 比作 TCP/IP 没错，但别忘了互联网值钱的部分，是 TCP/IP 之上那层身份与问责长出来之后才有的。

agent 生态正处在同一个时刻。连接已经标准化，开头那个"乐于助人的下午"会越来越多——因为连上太容易了。接下来一两年真正稀缺、也真正值钱的，不是又一个连接协议，而是协议背后那个会强制权限、会留痕、还不用你手写的工具层。它不解决一切，但没有它，剩下的都不敢上线。

```bash
npm i -g @objectstack/cli && os start
```

声明一个对象和它的权限，让 agent 通过工具去越权改一条它无权改的数据——看运行时怎么当场拦下，并把这次尝试也记进账里。
